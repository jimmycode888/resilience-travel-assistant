## 0 定位（全组共识，写进每个 PR 描述）

第一阶段证明了概念；第二阶段把它升级成**可交互、可扩展、可接真实数据的 MVP**。

我们不是重新做导航软件，而是在地图与现有导航能力之上加一层**出行决策增强层**：

- 普通地图回答：怎么走最快？
- 我们回答：**几点走更合适、哪条更稳、哪里挤、哪里险、准时到达概率多少、出问题怎么办。**

第二阶段真正要交付的不是"更多功能"，而是这条闭环：
**地图交互 + 实时数据 + 风险计算 + 可靠性预测 + 决策推荐 + Plan B**

**重点工作流有两条：① 出行决策增强（Risk / Reliability / Plan B）　② 跨境出行（深港）**

## 2 责任制：每个人负责"结果"，不是"任务"

> **A：系统跑不跑得通，我负责。**
> **B：数据准不准、能不能拿到，我负责。**
> **C：推荐有没有价值，我负责。**
> **D：地图和交互能不能用、QA 有没有兜住，我负责。**
> **E：用户看不看得懂、界面好不好用，我负责。**

工作量基准（coding 工作量占比）：**A ≈ 30–35%**，B / C / D 各 **≈ 20–25%**，E 走独立设计流。

A 超出别人的那部分**不是写更多代码**，而是：系统设计、接口定义、合并冲突、debug、集成、技术决策。所以 A 从第一天起就不要去做 UI 小功能，否则会拖住整个项目。

### 关键结构草案（A 在第 1 轮内定稿）

```ts
// Journey：后续所有风险计算的基础。跨境行程 = 香港境内段 → 通关段 → 深圳境内段
interface Segment {
  id: string;
  mode: "mtr" | "bus" | "minibus" | "walk" | "tram" | "ferry" | "cross_border_bus" | "hsr";
  /** 跨境支持：判断该段属于哪一侧，以及是否为通关段 */
  kind: "in_hk" | "border_crossing" | "in_sz";
  line: string | null;
  from: PlaceRef; to: PlaceRef;        // PlaceRef 含 id / name / lat / lon / kind / side
  departAt: string; arriveAt: string;   // ISO +08:00
  durationMinutes: number;
  geometry: [number, number][];         // [lon, lat] 折线，供地图绘制与路段点击
  viaStations: string[];                // 涉及站点，供中断/拥挤判定
  viaDistricts: string[];
  /** 通关段专属：排队时间区间（不是精确值）+ 置信度 */
  border?: { portId: string; queueMinutesRange: [number, number]; confidence: "high" | "medium" | "low" };
}

// 每个数字都要能溯源（延续第一阶段 basis 机制）
interface DataEnvelope<T> {
  value: T;
  source: string;                       // "香港天文台" / "MTR" / "入境处"
  sourceUrl: string | null;
  updatedAt: string;
  confidence: "high" | "medium" | "low";
  quality: "live" | "cached" | "fixture";
}

// 风险：五因子 + 总分
interface RiskBreakdown {
  weather: number; crowd: number; disruption: number; transfer: number; border: number; // 0–100
  overall: number;
  weights: { weather: number; crowd: number; disruption: number; transfer: number; border: number };
  factors: RiskFactor[];                // 每条含 { claim, evidence, source }
  confidence: "high" | "medium" | "low";
}
```

## 5 跨境工作流（重点之一）

跨境不是"多一个目的地"，而是一条**独立的工作流**，因为它改变数据结构、风险模型、Plan B 语义和数据来源。

### 5.1 目标走廊（Demo 主干）

```text
香港侧起点（如中环）
  ↓  香港境内段（东铁线 / 跨境巴士 / 高铁）
口岸通关段（落马洲 · 罗湖 · 深圳湾 · 皇岗）
  ↓  深圳境内段（地铁 / 步行）
深圳侧目的地（如福田 · 会展中心 · 市民中心）
```

至少保证**一条跨境走廊**全链路可跑通，作为路演主干之一。

### 5.2 跨境段的三个结构要求（A 冻结）

1. `Segment.kind` 必须能区分 `in_hk` / `border_crossing` / `in_sz`。
2. 通关段必须带 `queueMinutesRange`（**区间**）+ `confidence`，不得是单点精确值。
3. 口岸是**一等公民节点**（不是普通 POI）：需要 `portId`、开放时间、可通行方式。

### 5.3 第五个风险因子：Border Risk（通关风险）

境内行程用原来的四因子；**跨境行程加 `border` 因子**：

| 行程类型 | Weather | Crowd | Disruption | Transfer | Border |
|---|---|---|---|---|---|
| 境内 | 0.25 | 0.25 | 0.35 | 0.15 | 0 |
| **跨境** | 0.15 | 0.20 | 0.25 | 0.10 | **0.30** |

规则：`border` 权重为 0 时，其余因子按比例归一化。四种路线模式只调权重，不换算法。

Border Risk 输入因素：口岸类型与规模、时段（早高峰北向 / 晚高峰南向）、星期与节假日、天气（黑雨/台风时口岸状态）、交通中断（东铁线中断会挤爆口岸）、历史排队规律。

输出：**Low / Medium / High + Confidence + 预计排队时间区间**。

### 5.4 跨境 Plan B 的语义与境内不同

- 境内 Plan B = **换线路**；跨境 Plan B = **换口岸**（这才是用户真正需要的那条建议）。
- 示例触发条件：

```text
若落马洲口岸排队 > 30 分钟        → 改走深圳湾口岸
若东铁线服务中断                  → 改乘跨境巴士
若黑雨/台风生效                   → 口岸可能限流，重新计算全部路线
```

- **必须校验口岸开放时间**：非 24 小时口岸不得作为当前时段的 Plan B。

### 5.5 数据可得性（B 必须如实核对，不得编造）

| 数据 | 现实可得性 | 处理方式 |
|---|---|---|
| 东铁线 / 跨境巴士服务状态 | 相对可得（公开） | 走 live 适配器 |
| 口岸开放时间与状态 | 相对可得（公开） | 走 live 或低频缓存 |
| **各口岸实时排队时间** | **官方公开渠道不一定存在** | 用"历史规律 + 时段模型"输出 **区间 + Confidence（low/medium）**，明确标注为**估算** |
| 深圳侧交通数据 | 因源而异 | 拿不到就走 fixture，并如实标注 |

> ⚠️ **硬约束**：严禁展示精确到分钟且没有置信度的排队时间。宁可显示"约 20–40 分钟（估算，置信度中）"，也不要显示"排队 27 分钟"。

### 5.6 跨境的验收标准（追加）

1. 一条跨境行程全链路跑通：香港起点 → 口岸 → 深圳目的地。
2. 该行程必须展示 **Border Risk**（等级 + 置信度 + 排队区间）。
3. 必须给出至少一条**换口岸**的 Plan B 及触发条件。
4. 地图需覆盖深港两地（OSM 瓦片天然覆盖，无额外密钥成本）。
5. 排队数据必须显示为区间 + 置信度，且文案标注"估算"。

## 6 第 0 天必须定的技术选型（A 决策，阻塞 D 和 B）

| 决策 | 推荐默认 | 理由 |
|---|---|---|
| 地图渲染 | **MapLibre GL JS 或 Leaflet + OSM 瓦片** | 零密钥、可离线降级，符合第一阶段"不填密钥也能完整运行"的底线；且天然覆盖深港两地 |
| 路线来源 | **Route Adapter 接口 + 两个实现**：`fixture`（离线确定性）+ 1 个真实 provider | 断网仍能演示；换 API 不改上层 |
| 商业地图 SDK | **不接入**，只做深链跳转 | 第二阶段不需要逐步导航 |
| 真实路线 provider | A 试通后定，优先兼容 OSRM 风格接口 | 接口统一，避免绑定单一商业 SDK |
| 地图跳转 | Google Maps / Apple Maps / 高德 深链 URL | 一行 URL 的事，别做 SDK |

> ⚠️ `NEXT_PUBLIC_` 前缀的变量会进浏览器包，**禁止放进任何密钥**；密钥只放 `.env.local` 并列入 `.gitignore`。

## 8 Git 与合并规则

```text
main                        ← 只接收通过集成门的 dev
dev                         ← 集成分支，任何时刻必须可运行
feature/core-engine         ← A
feature/data                ← B
feature/decision            ← C
feature/map                 ← D
feature/ui-assets           ← E（或直接在 Figma + docs/ui-spec-v2/）
```

规则：

1. 只从 `dev` 切分支，PR 合回 `dev`；**禁止直接推 `main`**。
2. 每轮集成门通过后，由 A 把 `dev` 合入 `main` 并打 tag（`phase2-r1` / `phase2-r2` / `phase2-r3`）。
3. 一个 PR 只解决一个问题，必须写"怎么验证"（跑哪条命令、看什么结果）。
4. **涉及 `src/lib/types/**` 的 PR 必须 A 批准**。
5. 禁止提交：`.env` / 真实密钥 / `node_modules` / `.next` / 个人绝对路径。
6. 谁发现 `dev` 不可运行，谁优先修集成，不继续堆新功能。

## 9 完成定义 DoD

第一阶段的 7 条继续有效（明确输入输出、四类状态、复核、已合并部署、无密钥泄露、可复现、时间戳与不确定性可见）。第二阶段追加：

8. **新增的每个数字都必须带 `{source, updatedAt, confidence}`**，缺一个不得上线。
9. **不得展示未经校准的精确概率**：准时概率、口岸排队时间都必须带置信度与说明文案，沿用第一阶段"到达信心 高/中/低"的做法。
10. **地图功能必须有降级路径**：无定位权限、无网络、无路线三种情况都不能白屏。
11. **AI 层输出必须可追溯到算法结果**（沿用 `basis` 机制），AI 不得新增事实。
12. **每个 live 数据源必须有 timeout → cached → fixture 三退路**，且 `dataQuality` 如实标注。
13. 风险等级只输出 Low / Medium / High（+ Confidence），**不声称知道精确人数或精确排队时间**。
14. **跨境行程必须校验口岸开放时间**，不得把已关闭的口岸作为 Plan B。

## 11 验收标准

第二阶段完成后，必须能稳定跑通这条链路（**含一条跨境行程**）：

```text
用户打开地图 → 看到自己位置
→ 搜索或点击选择目的地（含深圳侧地名）
→ 获得至少 2 条候选路线
→ 获取实时天气与交通信息
→ 分别计算路线风险（含 Border Risk）
→ 显示 Crowd Risk
→ 计算准时到达概率
→ 推荐最佳路线 + 最佳出发时间
→ 提供 Plan B（跨境为换口岸）
→ 地图显示风险图层
→ 点击开始导航，跳转现有导航软件
```

**验收通过 = 这条流程能稳定跑通，且每个数字都能说出"来自哪里、多久前更新、可信度如何"。**

## 12 风险与对策

| 风险 | 对策 |
|---|---|
| 地图 / 路线 API 拿不到 | Adapter + fixture 双实现，**第 1 轮就把 fixture 版跑通**，真实源后接 |
| **口岸实时排队数据拿不到** | 如实降级为"历史规律 + 时段模型"的区间估算 + 低置信度标注，**绝不编造精确值** |
| 五个人互相踩代码 | `src/lib/types/**` 单一所有者 + CR 流程 + 目录所有权表 |
| Crowd / On-time / 排队变成"编造数字" | 定性等级 + Confidence + 文案标注"估算" + 依据可溯源 |
| Replay 模式被当成主功能做 | 它是 P2/P3，最后一轮才动，只做时间轴 + 重算 |
| A 成为瓶颈 | A 第 1 轮只做接口与骨架，不接 UI；集成窗口集中在下午 |
| 跨境把范围撑爆 | 跨境只保证**一条走廊全链路**，不做全口岸覆盖、不做排队预测校准 |
