## 三、估算模型（可解釋）

```
排隊區間 = 先驗區間(口岸性質 × 時段) + 週末 + 深夜修正 + 惡劣天氣 + 鐵路中斷
         + 口岸公告事件 + 運力變薄(實測班距 vs 常態班距 ×1.6)
```

- **口岸性質**：`rail`（落馬洲、羅湖）/ `coach`（深圳灣、香園圍、皇崗）/ `remote`（文錦渡，班次疏落）。
- **時段**：北向高峰 07:00–10:00、南向高峰 17:00–20:00、深夜 22:30 後。
- **口岸未開放 → 不給數字**，直接判不可行（比估排隊更重要）。
- 每個數字都輸出**逐項依據**，可回溯到「哪條先驗 + 哪個信號 + 加了多少」。

## 四、三退路（逐口岸）

`live → cached → fixture`，**逐口岸**判定：深圳灣取得到、文錦渡取不到時，
不會讓文錦渡的失敗把深圳灣一起降級。

- 讀取快取 30 秒；來源效期 2 分鐘；只存在記憶體，重啟即清空（不引入資料庫）。
- 已知的限制：整體品質只由**真的有信號來源**的口岸決定，皇崗／文錦渡不會拖垮其他口岸。

## 五、怎麼啟用

預設**完全不連網**（沿用第一階段慣例）。設定任一環境變數即啟用：

```dotenv
HKO_OPEN_DATA_BASE_URL=https://data.weather.gov.hk/weatherAPI/opendata/weather.php
TD_SPECIAL_TRAFFIC_NEWS_URL=https://www.td.gov.hk/en/special_news/trafficnews.xml
MTR_NEXT_TRAIN_ENABLED=1
# 或只開 B 的正式資料：
TEAM_LIVE_DATA_ENABLED=1
```

未設定時 `resolveRouteData` 回 `null`，正式端點維持保守路徑——**不用 fixture 冒充正式資料**。

## 七、誠實邊界（**這些一定要一起講**）

1. **沒有任何來源直接觀測排隊**——全部是間接代理，所以**置信度上限是 `medium`**，永遠不會 `high`。
2. **班距是時刻表驅動，不是需求驅動**，不能反推客流。
3. **基礎區間是假設，未經歷史排隊資料校準**。
4. **皇崗、文錦渡沒有公開信號**，只有先驗估算 + low。
5. **口岸開放時間仍是未核實值**（`geo/ports.ts` 的 `coordinatesVerified: false`）——判定開關的地基還沒穩。
6. 港鐵只有 `isdelay = Y/N`，**沒有延誤分鐘數**；且「沒有延誤旗標」一律報 `unknown`，**不報 `ok`**。
