## 当前可开展的测试

可以做 fixture 界面的形成性测试：输入、路线/地图联动、ETA/定性信心理解、风险证据、A 基础推荐与 C 未接入的区别，以及 mock C 行动状态与演示/降级资料识别。
不能测试真实 B 数据准确性、C 模型有效性、预测窗口可靠性、真实导航或未来班次；正式端点当前 404。此轮观察不可写成正式接口验收。

## 准入清单

- 主持人打开发布链接 /journey-team；记录 VERSION.json 中 BUILD_ID 与源码摘要，不使用 5173、5180、8455。
- 确认页面题头为 D 第二阶段 v2.0，数据接入选 D 测试 fixture；正常情景显示 C 正式决策未接入。
- 核对最新 QA 运行结果及已知问题，完成一轮真实手机触控、真人键盘走查；若参与者依赖读屏，先做对应读屏预检。
- 保持本地服务/团队预览可达；地图瓦片可联网，失败时仍有文字路线，不要求离线首次加载。
- 获取参与者同意，记录匿名代号，不收集姓名、电话、精确住址。录屏另行征得同意；交付包没有真实参与者数据。
- 说明“这是界面试验，请勿据此实际出行”，不提前解释推荐、信心或资料徽章，以免诱导答案。
- 五位由用户招募，尽量不参与开发；不得填造身份或观察。P01–P05 是空白记录位置。

## 执行步骤

1. 每位从刷新后的 /journey-team 开始，主持人先选 fixture/normal。默认回放日期 2026-10-13；可调整日期，但不声称该日实况。
2. 依 TASK_CARDS.md 顺序提供任务，每项只读任务文字。让用户边操作边说想法，不提示按钮位置。
3. 遇到卡住先记录原话、耗时及画面，再按需要给帮助；记录帮助次数，不能把主持人代操作算独立成功。
4. 涉及 mock 状态时，主持人切情景并明确记录情景。窗口为 D mock 测试值；不问“是否相信它能准时”。
5. 不可行卡仍可打开供解释，不能作为出发选择；如果用户误解，先记录，再说明。
6. 每项填 USER_TEST_RECORDS.csv。最后用中性问题追问：哪些词难懂？资料缺失时会怎样处理？哪里会误以为实况？
7. 按 USER_TEST_SUMMARY.csv 汇总真实记录；分母为实际执行人数/任务，帮助后成功与独立成功分开，未执行留空。
8. 收集真实设备/浏览器信息和键盘/读屏问题，按 ISSUE_TEMPLATE.csv 归档。A/B/C/E 再按职责确认，不代发消息。
