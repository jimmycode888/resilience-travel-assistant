# 第二阶段任务卡（仅对应已实现功能）

| 编号 | 给参与者的任务 | 主持人准备 | 观察标准（不要先读给参与者） |
|---|---|---|---|
| T1 | 安排中环到福田的行程，出发 08:00，希望 11:00 前到达。比较后说说有哪些选择。 | fixture / normal，香港时间；可以改变偏好、口岸 | 能输入并提交；知道所有时间为香港时间，能发现可用候选 |
| T2 | 选另一条路线，说说地图和详情有什么变化。用键盘再试一次。 | normal；鼠标/触控及键盘可用 | 卡片/地图联动；不可行卡为查看，不是执行按钮 |
| T3 | 说出选中路线何时可能到达，信心是什么意思。你会把它看成准时百分比吗？ | normal；不提前说明答案 | 读 ETA 上下界与定性信心，看到 confidenceNote，未把规则分数当概率 |
| T4 | 找一个你在意的风险及依据；看通关等候和信心。 | normal 或 critical | 找五因子展开证据；排队区间/估算/信心三件套；critical 仅为人流 |
| T5 | 页面有正式行动建议吗？如果没有，你会依据什么继续判断？ | normal：decision=null | 区分 A 基础推荐与 C 未接入；不会自己补出发或切换时间 |
| T6 | 查看主路、备选及出发窗口。你认为这些数据来自哪里？再看没有备选时会怎样处理。 | go → no-backup，均为 D mock | 能看备选；识别 mock 窗口，不把无备选理解为安全保障 |
| T7 | 现在暂缓、服务中断或赶不上期限，你会怎样理解页面？ | hold → disruption → deadline，可分轮 | 不把不可行/超时方案当出发推荐；理解 hold/unavailable 与路线查看的区别 |
| T8 | 找资料来源及时间。如果资料缺失、过期或回退，你会怎么做？哪些提示说明不是实况？ | missing → stale → timeout（模拟上游回退） | 识别 fixture、来源、过期和低信心；不把回放评估时间当实时更新时间 |

未纳入任务：真实导航、定位准确度、费用预测、Plan C、连续回放、AI 对话、真实出发窗口模型。它们不属于此正式契约页面已完成的可测功能。
