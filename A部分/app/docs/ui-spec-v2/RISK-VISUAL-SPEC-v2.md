# 风险视觉规范 v2（Risk Visual Spec）

Owner **E** ｜ 消费方 **D** ｜ 版本 v2.0 · 2026-10-10
配套：`JOURNEY-VISUAL-SPEC-v2.md`（主文件）、`MAP-LAYERS-SPEC-v2.md`、`QA-CHECKLIST.md`

> 本文件只规范**呈现**。风险等级的**判定**由 A 的 `risk/thresholds.ts` / `risk/engine.ts` 决定，E 与 D 都不得修改。

---

## A. 范围与原则

1. E 是视觉规范的唯一负责人；D 按本规范实现，不自选颜色。
2. **不得由开发自行决定风险等级颜色。**
3. **风险不能只靠颜色**：一律「颜色 + 文字标签 + 非颜色符号」三者并存。
4. **不得通过视觉暗示掌握精确人数或排队时间。**
5. 用户可见文案使用香港繁体中文。
6. 估算/演示数据必须有标识（`演示估算 · fixture`、`排隊估算`、`信心：低`）。
7. 本规范不改变任何算法、契约或数据。

## B. ⚠️ 先厘清：现有代码里有三种不同的「等级」

| # | 概念 | 型别 / 出处 | 允许值 | 档数 |
|---|---|---|---|---|
| 1 | **路线风险** | `RiskLevel` — `types/risk.ts:20` | `low` / `medium` / `high` | **3** |
| 2 | **人流信号** | `CrowdSignal.level` — `types/risk.ts:136` | `low` / `medium` / `high` / **`critical`** | **4** |
| 3 | **视觉规格** | `JourneyVisualSpec.risk` — `ui-contract.ts:4` | `low` / `medium` / `high` / **`critical`** | **4** |

**关键事实：**

- `riskLevelOf(score)`（`risk/thresholds.ts`）只回传 3 个值，`RISK_LEVEL_LABELS` 只有 3 键。
- `estimateCrowd()`（`journey/analysis.ts:17`）**会**产出 `critical` —— 但那是**人流信号**。
- `types/risk.ts` 的 `RiskBreakdown` 注释明确写：「本模型输出的是定性风险等级（low / medium / high）」。

→ **结论：`critical` 目前不是路线风险等级。** 它是「人流信号」的真实取值，并且已在视觉规格中预留了槽位。

## D. `critical` 的定位（⚠️ Pending Confirmation）

### D.1 现状

| 项目 | 现值（`REFERENCE_JOURNEY_VISUALS`） |
|---|---|
| label | `極高風險` |
| color | `#84282c` |
| symbol | `!!` |

### D.2 色相分析（为什么现在的四色实际上只有三色）

| 等级 | 色相 | 亮度 L* |
|---|---|---|
| low 绿 | **175°** | 0.135 |
| medium 琥珀 | **34°** | 0.202 |
| high 红 | **359°** | 0.146 |
| critical 暗红 | **357°** | 0.066 |

- `high`(359°) 与 `critical`(357°) 的**色相差只有 2°** —— 两者是**同一个红色**，只靠明度区分。
- 因此在色盲（尤其红绿色盲）或低对比环境下，**`high` 与 `critical` 无法靠颜色区分**。
- 同理，若把 `critical` 改成橙色（H≈33°），它与 `medium` 琥珀（H 34°）的**色相差只有 1°** —— 依然无法区分。

**这是一个物理限制，不是选色问题**：白底要达 4.5:1 的文字色必然是暗色，
在「黄→红」这段色相里塞不下两个可区分的暗色。

### D.3 E 的建议（两个方案，均待 A 确认）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **D-A（推荐）** | 路线风险维持**三色**；`critical` 保持"更深一阶的红" `#84282c`，**强制**以符号（`◆`）与文字（`極高／極高風險`）区分 | 零迁移、语义安全（不新增算法等级） | 团队「橙」的要求未以色相满足 |
| **D-B** | `critical` 改为橙色 `#c2710c`（图形）/ `#a85c00`（文字） | 名义上满足「橙＝较高」 | 与 `medium` 琥珀色相几乎重合，**实际仍不可区分**，且 3.71:1 未达文字标准 |

**E 的结论：方案 D-A。** 并明确建议团队**不要试图靠色相表达四档** ——
第四档必须由**符号 + 文字标签**承担（本规范已要求所有等级都带符号与标签）。

> ⚠️ **无论选哪个方案，都不得把 `critical` 接进路线风险算法。**
> 是否把 `critical` 明确定义为「人流信号最高档」（例如在 `ui-contract.ts` 的注释中写明 `crowd-only`），
> 属 **A 的契约决定**，E 不自行修改 TypeScript。

## E. `unavailable` —— 这不是风险等级

`JourneyVisualSpec.unavailable` 的型别虽然是 `RiskVisualToken`，但**语义属于「路线可行性」**：

| 项目 | 值 |
|---|---|
| 触发条件 | `AnalyzedJourney.eligible === false`（由 `exclusionsFor()` 判定） |
| 标签 | `不可行` |
| Token | `--route-unavailable` |
| 颜色 | `#8b99a1`（灰） |
| 白底对比度 | **2.93:1** ⚠️ 低于 3:1 |
| 文字色建议 | **`#5f6b73`**（5.47:1） |
| 符号 | `×` |
| 线型 | **虚线（建议 `2 5`，与通关段区分）** |
| 依据 | `exclusions` 逐条红字说明（如「XXX在預計通關時段未開放」） |

**D 必须做到的三件事：**

1. **不得把 `unavailable` 画成「零风险」**（不得用绿色、不得省略虚线）。
2. **不得与低风险混淆**：低风险是**实线 + 有颜色**；不可行是**灰 + 虚线 + `×`**。
3. **`×` 符号目前未在 UI 出现**（只有颜色 + 文字）→ 需补（P1）。

**线型冲突（P1）**：现况 `JourneyMap.tsx` 中，`border_crossing` 与 `!eligible` **共用同一条虚线 `'7 7'`**，
两者只靠颜色（紫 / 灰）区分 —— 违反「不只靠颜色」。建议：

| 用途 | 线型 | 颜色 |
|---|---|---|
| 通关段 | `'7 7'` | `#8653ad` 紫 |
| 不可行 | **`'2 5'`** | `#8b99a1` 灰 |

## F. 非颜色符号规范

### F.1 符号表

| 等级 | 符号 | 名称 | 说明 |
|---|---|---|---|
| `low` | `●` | 实心圆 | 与 `REFERENCE_JOURNEY_VISUALS` 一致 |
| `medium` | `▲` | 实心三角 | 与 `REFERENCE_JOURNEY_VISUALS` 一致 |
| `high` | **`■`** | 实心方 | **改动**（原 `!`，与 `!!` 过近） |
| `critical` | **`◆`** | 实心菱形 | **改动**（原 `!!`，与 `!` 过近） |
| `unavailable` | `×` | 叉号 | 沿用；但需**实际出现在 UI** |
| `border_crossing` | `⋯`（或用虚线本身） | 通关 | 已有虚线，符号可选 |

### F.2 要求

1. **不看颜色也能理解等级** —— 形状 + 文字标签。
2. **不同等级的符号不能过度相似** —— `● ▲ ■ ◆` 在 12–14px 下仍可区分。
3. **不能只用绿/黄/橙/红表达风险。**
4. **不要因加图标而使地图过度拥挤** —— 符号只出现在**图例、风险卡、路线卡**；
   **地图折在线不逐段画符号**（避免地图噪音），地图以线色 + 线型表达，图例负责解释。
5. **优先复用现有图标体系**：现况 `JourneyPlanner.tsx` 用**纯文字**（`LEVELS`）表达等级，
   不需要引入图标库；上述几何符号可用 Unicode 字符直接渲染，**无需新增依赖**。

### F.3 每个符号的规范化名称

| Token | 符号 | 用途 |
|---|---|---|
| `symbol.risk.low` | `●` | 图例、风险卡 |
| `symbol.risk.medium` | `▲` | 同上 |
| `symbol.risk.high` | `■` | 同上 |
| `symbol.risk.critical` | `◆` | 人流/因子卡（Pending） |
| `symbol.route.unavailable` | `×` | 图例、路线卡 |

## G. 可访问性要求

| 要求 | 标准 | 现状 |
|---|---|---|
| 文字对比度 | ≥ 4.5:1（白底） | `medium` 文字需改用 `#8a5209`；`unavailable` 文字需改用 `#5f6b73` |
| 图形/线条对比度 | ≥ 3:1（相邻色） | `unavailable #8b99a1` 仅 2.93:1 → 建议线条加**白色描边**，或文字承载信息 |
| 不只靠颜色 | 必须 | 现况 `border_crossing` 与 `unavailable` **只靠颜色** → 需改线型 |
| 色盲友好 | 推荐 | `low`(绿) 与 `medium`(琥珀) 对红绿色盲仍可区分（明度差 L 0.135 vs 0.202）；但 `high` 与 `critical` 不可 → 靠符号 |
| 触控尺寸 | ≥ 44px | 地图工具栏 checkbox `min-height:32px` → **低于标准**（P2） |

**地图折线可读性（P1，E 提案）**：
OpenStreetMap 底图颜色不可控，深浅不一的底图上单一线色可能失效。
建议为路线折线加**白色描边**（Leaflet 做法：同一条折线先画 `color:#fff, weight: width+3`，再画彩色主线），
使线色在任意底图上都保持可辨 —— 这与「地图是重度信息区、必须克制且清晰」一致。

## H. 风险在 UI 各处的呈现

| 位置 | 元素 | 呈现方式 | 对应字段 |
|---|---|---|---|
| 地图 | 路线折线 | 颜色 = `risk.*`；通关段紫虚线；不可行灰虚线；**加白色描边** | `RouteRisk.level`、`JourneySegment.kind`、`eligible` |
| 地图 | 图例 | 文字 + 符号 + 色块（见 MAP-LAYERS §图例） | — |
| 地图 | 路段弹窗 | `路線 · 線路 · from → to · N 分 · 排隊估算 a–b 分` | `JourneySegment.*` |
| 路线卡 | `整體風險：X · 信心：Y` | `LEVELS[risk.level]` + `LOW/MED/HIGH` 文字；**加符号** | `RouteRisk.level`、`reliability.onTimeConfidence` |
| 风险详情卡 | 五因子 `<details>` | 因子名 + 等级（符号 + 文字）+ `claim` + `evidence` + `source` | `RiskFactor.*` |
| 风险详情卡 | 风险评估可信度 | **目前未显示** → 建议在卡片标题显示 `信心：低/中/高` | `RiskBreakdown.confidence` |
| 人流 | 路线卡/因子卡 | **目前未单独标示** → 建议在 `crowd` 因子上标注 `人流 · 低信心（演示規則）` | `CrowdSignal.level/confidence/evidence` |
| 状态条 | hold / unavailable | `暫緩非必要行程` / `暫無可行方案` 标题 + 琥珀/灰状态条 | `JourneyAnalysis.action` |

**硬约束（重复强调）**：任何位置都不得出现「精确人数」或「精确排队分钟数」。
排队一律 `queueMinutesRange` 区间 + `confidence` + 「估算」字样。
