## 0. ⚠️ 现状核对（必须先知道）

现有实作（`JourneyPlanner.tsx` 第 16–18、94–99、122 行）：

```tsx
const REPLAY = [
  { label: '正常',     scenario: 'normal',     offset: 0  },
  { label: '暴雨',     scenario: 'heavy_rain', offset: 20 },
  { label: '東鐵中斷', scenario: 'disruption', offset: 40 },
];

function play(index: number) {
  setReplay(index);
  const frame = REPLAY[index]!;
  const input = { ...request, departAt: addMinutes(...frame.offset).slice(0,16), scenario: frame.scenario };
  setRequest(input); void run(input);          // ← 直接重跑，替換整個 analysis
}
```

| 事实 | 说明 |
|---|---|
| 时间轴是 `<input type="range" min=0 max=2 step=1>` | **只有 3 格**（正常/暴雨/中断），**不是连续时间** |
| `offset` 分别 `0 / 20 / 40` 分钟 | 从 `INITIAL.departAt`（08:00）起算 → `08:00 / 08:20 / 08:40` |
| `play()` 直接 **替换** `analysis` | **不保留上一份快照** → **当前无法做前后对比** |
| `<div>` 下有三个刻度标签 | `08:00 正常` / `08:20 黑雨` / `08:40 東鐵中斷` |
| 色系 | `.journey-replay` 深色卡（`#153d50`），滑块 `accent-color:#86d6c6` |

**结论**：现状是「**情景回放**」（3 档离散切换），**不是**「时间轴模拟」（连续时间 + 差异对比）。
本规范分两部分：**A. 现有回放的精修**（可立即实作）｜**B. 差异对比**（需依赖项，标注 Pending）。

## 1. 交互模型

```
用戶拖动时间轴
   ↓
本地立即更新「當前時間」顯示（不等计算）
   ↓
顯示「正在重新計算」狀態（保留舊結果）
   ↓
取得新分析結果
   ↓
顯示對比：原方案 vs 新方案 + 變化摘要
```

**原则**：
1. **拖动时不阻塞 UI** —— 显示旧结果 + 状态条。
2. **不虚构差异** —— 只对比两次真实分析结果的字段差。
3. **说得清「变了什么」** —— 用文字 + 符号，不只靠颜色。
4. **演示数据与真实数据区分** —— 复用 `演示估算 · fixture` 徽章。

### 2.1 时间轴位置与层级

| 项目 | 规范 |
|---|---|

| 元素 | 现状 | E 提案 |

## 3. 三个界面状态

### A. 尚未调整时间轴

```
┌ .journey-replay（深色卡）──────────────────┐
│ 情景回放 · 拖動時間軸試看推薦變化             │  ← 13px
│                                            │
│ ●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━○ │  ← 把手在第 1 格
│                                            │
│ 08:00 正常    08:20 黑雨    08:40 東鐵中斷   │  ← 11px → [改] 12px
└────────────────────────────────────────────┘
下方：完整結果（三條候選、風險、ETA、何時出發、Plan B、資料與限制）
```

| 项目 | 规范 |
|---|---|
| 可见内容 | 完整结果（等同不调整时的正常结果） |
| 提示文案 | `情景回放 · 拖動時間軸試看推薦變化` |
| 是否显示对比 | ❌ 无对比（无「上一版」可比） |
| 是否显示地图 | ✅ |
| 数据可信度 | `演示估算 · fixture` |
| Token | `--c-bg-deep` `--c-text-on-deep` |
| 移动端 | 滑块触控 ≥44px；刻度可换行 |
| 验收 | 初次进入时把手在第 1 格、无对比区 |

### B. 拖动时间轴并重新计算

```
┌ .journey-replay（深色卡）──────────────────┐
│ 情景回放 · 08:40 東鐵中斷                    │  ← [改] 顯示時間 + 情景
│ ○━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━●━━━━━○ │  ← 把手在第 3 格
│ 08:00 正常    08:20 黑雨    08:40 東鐵中斷   │
└────────────────────────────────────────────┘
┌ .journey-status（中性狀態條）───────────────┐
│ 正在重新比較；下方保留上一次結果。            │  ← [現] 逐字保留
└────────────────────────────────────────────┘
下方：**上一次的结果**（不变，避免闪烁）
```

| 项目 | 规范 |
|---|---|
| 触发 | `play(index)` → `setReplay` → `run()`，`loading=true` |
| 表现 | 时间轴立即更新到新位置；`journey-status` 出现；**下方结果保持旧值** |
| 提示文案 | `正在重新比較；下方保留上一次結果。`（`[現]` 已实作） |
| 是否保留原有内容 | ✅ **必须保留**（避免空白闪烁） |
| 是否保留地图 | ✅（旧折线保留） |
| 可执行操作 | 可继续拖动（`activeController.abort()` 会取消上一次请求） |
| 数据可信度 | 旧结果的徽章保持原样，**不得**提前显示新结果 |
| 移动端 | 滑块拖动时**不触发页面滚动**（现有 `scrollWheelZoom:false` 类似思路） |
| 验收 | 拖动后 ≤100ms 出现状态条；旧结果仍在；无白屏 |

### C. 计算完成并对比调整前后

```
┌ 變化摘要 ───────────────────────────────────┐
│ 由 08:00 正常 → 08:40 東鐵中斷               │  ← 前 → 後
│                                            │
│ ▲ 推薦路線   中環→福田 A   →   深圳灣 B      │  ← 變了（用符號）
│ ▲ 整體風險   低            →   高            │
│ ▲ 到達時間   09:12–09:41   →   09:38–10:24   │
│ = 比較偏好   綜合推薦       →   綜合推薦      │  ← 未變
│ = 起終點     中環 → 福田    →   中環 → 福田   │
│                                            │
│ ⚠ 落馬洲、羅湖口岸在預計通關時段未開放。      │  ← 新出現的排除原因
│ 演示估算 · fixture                          │
└────────────────────────────────────────────┘
下方：新結果（與 A 狀態同結構）
```

| 项目 | 规范 |
|---|---|
| 触发 | 新结果返回且**存在差异** |
| 表现 | 结果区顶部出现「變化摘要」区，**新结果替换旧结果** |
| 对比字段（**只比真实存在的字段**） | `recommendedRouteId`、`risk.level`、`reliability.etaRange`、`onTimeConfidence`、`action`、`mode`、`origin/destination`、`planB.routeId`、`exclusions`、`departureOptions[最佳]` |
| 变化符号（**非颜色**） | `▲` 变差 / `▼` 变好 / `=` 未变 / `＋` 新增 / `－` 消失 |
| 无差异时 | 显示 `本次調整未改變建議。` 并**不渲染对比表** |
| 数据可信度 | 对比区底部显示 `演示估算 · fixture` |
| 移动端 | **上下堆叠**（`原 08:00 正常` ↑ / `新 08:40 東鐵中斷` ↓），差异行加前导符号 |
| 验收 | 每条差异都能在两次 `JourneyAnalysis` 中找到对应字段；无编造项 |

> ⚠️ **必须区分「变了」与「因为数据本身缺失而看起来变了」**：
> 若某字段在两次结果中任一为 `null`，显示 `—` 并加注 `資料未提供`，**不得**判为「变为 0」。

## 6. 移动端与可访问性

| 项目 | 规范 |
|---|---|
| 滑块触控 | 高度 `24px → 44px`（`[Proposed]`） |
| 拖动与页面滚动 | 拖动滑块时**不得**触发页面滚动 |
| 刻度标签 | `11px → 12px`；窄屏可换行，不截断 |
| 对比表移动端 | 上下堆叠；每条差异 **`原值 → 新值`** 在同一行，避免左右栏 |
| 差异符号 | `▲ ▼ = ＋ －` 均为文字字符，`aria-hidden` + 文字说明 |
| 屏幕阅读器 | 对比区 `role="status"`；差异行需可读（例：`推薦路線：由 A 改為 B`），**不能只输出符号** |
| 键盘 | 原生 `range` 支持方向键；`aria-label` = `演示情景回放` |
| 减少动态 | `prefers-reduced-motion` 时**不加过渡动画**（`.journey-shell` 已有全局规则） |
| 色彩 | 差异**不只靠颜色**（符号 + 文字） |

## 8. 演示数据与真实数据的区分（重复强调）

- Replay 的**全部**结果目前来自 `fixture`（`JourneyAnalysis.quality` 固定 `'fixture'`）。
- 因此时间轴必须**始终**携带 `演示估算 · fixture` 徽章，且**不得**暗示这是未来预测。
- 文案使用「情景回放 / 演示情景」，**不使用**「預測」「預計未來」等词。
- 若未来接入真实预报源，须先由 B/C 提供来源与置信度，届时再更新本规范。
