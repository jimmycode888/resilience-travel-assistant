## 1. 如何執行

無需安裝任何依賴（純 HTML + CSS + ES Module JS，零 npm 套件）。

```bash
cd "/workspace/八校黑客松/A部分/app/docs/ui-spec-v2/prototype"
python3 -m http.server 8455 --bind 0.0.0.0
```

**預覽地址**：`http://localhost:8455/`

> ⚠️ 必須用 HTTP 伺服器開啟（`app.js` 是 ES module，`file://` 直接開會被瀏覽器攔截）。

| 模式 | 網址 | 說明 |
|---|---|---|
| 一般模式 | `http://localhost:8455/` | 只顯示產品流程，**沒有**情景／狀態切換按鈕 |
| Demo 模式 | `http://localhost:8455/?demo=1` | 顯示演示控制面板（情景、頁面狀態、風險四色對照） |

## 6. 四類狀態與六項重點檢查（Demo 模式）

Demo 面板可切換：**Loading / Empty / Error / Degraded**。

| 重點情況 | 原型表現 |
|---|---|
| 無定位權限 | 黃色狀態條：`定位權限被拒絕，請在系統設定中允許定位，或自行選擇起點。` |
| 無網絡 | Degraded 狀態：`部分資料未能取得…已在本機使用相同演示規則計算` |
| 無可用路線 | 東鐵中斷情景：兩條路線標「不可行」+ 原因；標題改為「暫無可行方案」（若全部不可行） |
| 部分風險數據缺失 | Degraded 狀態 + 「部分來源未能取得…已如實排除，不以其他來源冒充」 |
| 某條路線不可用 | 卡片 tag `不可行` + 紅字原因 + 灰**虛線 2 5** |
| 口岸數據缺失 | 不顯示該口岸節點（不偽造） |
| 緩存數據可用 | 品質 chip 支援 `快取資料`（原型的 `sources` 可擴充；目前情境未觸發） |
| 僅演示數據可用 | **恆成立**：全程 `演示估算 · fixture` 徽章 |
| 口岸排隊可信度缺失或無法識別 | Demo 面板「口岸排隊可信度 → 缺失／無法識別」：顯示「可信度：未確認」，**不會**預設為「低」，也不會染紅 |

## 8. 三個 P0 的收斂結果（2026-10-13，E）

> 展開說明見 `../P0-VISUAL-RESOLUTION.md`。**設計規範已解決、原型已驗證；生產頁面的接線仍待 D 實施。**

| # | 事項 | 級別 | 現狀 | 原型做法 |
|---|---|---|---|---|
| 1 | `risk.critical` 的視覺語義（路線風險 vs 人流信號） | P0 | ✅ **已由 E 收斂** | 路線整體風險只有三檔；`critical` **只**作為人流信號顯示，文案固定「人流極高」，符號 `◆`，橙色 |
| 2 | 團隊「橙 = 較高」的歸屬 | P0 | ✅ **已由 E 收斂** | 橙**不**進入路線風險；路線風險中檔改用深金黃 `#8A6D00`（與橙 ΔE 31.7），第四色歸人流信號 |
| 3 | `BorderQueue.confidence` 的顯示 | P0 | ⚠️ **規範已定、生產未接線** | 原型讀真實欄位並支援四態（高／中／低／未確認）；生產頁面仍寫死「低信心」，待 D 修 |
| 4 | `--ink` 衝突（`#18222d` vs `#153d50`） | P1 | 待 D | 原型採用 `--c-text-primary: #18222d` + `--c-accent-deep: #153d50` 並存 |
| 5 | 最小字級 12px | P1 | 原型符合 | 原型**全程 ≥12px**（供 D 對照） |
| 6 | 不可行與通關段線型分離 | P1 | 原型已分離 | 通關 `7 7`／不可行 `2 5` ✅ |

**原型內的「口岸排隊可信度」測試值不是真實資料**：真實欄位（`Confidence`）只有 `high / medium / low`；
「未確認」是**UI 顯示態**，只在欄位缺失或無法識別時出現。Demo 面板已明確標示為演示測試值。
