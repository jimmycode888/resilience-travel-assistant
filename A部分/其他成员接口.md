# A 与 B/C/D/E 的接口（v1，2026-10-10）

采用本地团队工作流的分工：**B=数据，C=决策，D=地图与前端，E=UI**。
共享契约由 A 维护；成员实现自己的模块，通过接口组合，不直接改 A 算法。

## 统一入口

```ts
import { createTeamJourneyService, resolveRoutes } from '@/lib/integration';
import type {
  TeamJourneyModules, TeamJourneyRequest, TeamJourneyResult,
  DataEnvelope, RouteDataEnvelope, TeamDecisionResult,
} from '@/lib/types/team-integration';
```

可编译示例：`app/examples/team-integration.ts`。
契约测试：`app/src/test/team-integration.test.ts`。

`createTeamJourneyService(modules)` 返回：

```ts
(request: TeamJourneyRequest, evaluatedAt: string) => Promise<TeamJourneyResult>
```

`evaluatedAt` 为调用端一次取得的 ISO 时钟，测试可固定。不在风险算法中读取全局时钟。
这个入口供服务端集成；模块函数不能作为 HTTP JSON 发送。

## B → A：路线与实时信号

B 实现 `TeamJourneyModules` 的两个必填函数：

```ts
resolveCandidates(query: RouteQuery): Promise<RouteResolution>;
resolveRouteData(route: CandidateRoute, request: TeamJourneyRequest):
  Promise<RouteDataEnvelope | null>;
```

- `resolveCandidates` 调 A 的 `resolveRoutes({ query, providers, cache })`。自定义供应商遵循 `RouteProvider.fetch(query, signal)`，返回中立 `RawRoute[] | null`；不要让数据模块另写解析器。
- `resolveRouteData` 按每条候选返回 `RiskContext`：weather、service、incidents，以及可选 crowd、border。
- `RouteDataEnvelope` 必须含 `routeId / value / source / sourceUrl / updatedAt / expiresAt / confidence / quality`。时间需带偏移量；数据失效必须反映在 expiresAt。
- routeId 必须严格匹配候选 ID。禁止把第一阶段 R1 服务状态直接套进第二阶段 xb-1。
- 复合数据的 quality/confidence 必须采用参与来源的保守值。缺失返回 null；B 自行实现超时／缓存／fixture 回退。接口异常将向上抛出，API 层须显示错误或显式回退。
- A 会进一步采用路线与情境中较差的品质；过期或未来更新时间会降级。fixture 路线不会因实时天气而变为 live。
- 数据值的运行期格式清洗由 B 负责；TypeScript 不是外部 JSON 的校验器。

`RouteProvider`、`RawRoute`、`RouteResolution` 详见 `types/route.ts`；`RiskContext` 详见 `types/risk.ts`。

## C → A：人流、通关与决策

人流／通关信号可由 B/C 的组合层合入每条候选的 `RiskContext`：

```ts
crowd: { level: 'low' | 'medium' | 'high' | 'critical'; confidence; evidence }
border: { portId; queueMinutesRange: [min, max]; confidence; note }
```

不得编造精确人数；通关必须使用区间，并匹配口岸。不同口岸的信号不会被混用。
A 已算好风险、可靠性及可行性后，调用 C 可选函数：

```ts
decide(core: TeamCoreResult): Promise<TeamDecisionResult>;
```

`core.routes[]` 提供完整 candidate、assessment、eligible、exclusions、meetsDeadline 和数据来源。
C 返回：

- action：go / hold / unavailable；
- primaryRouteId、backupRouteIds；
- departureWindow：start / end / confidence / evidence 或 null；
- explanations：routeId / text / evidence[]；
- notices。

A 保护边界：不存在或被排除的路线不能被 C 选作主路／备选；严重天气暂缓不能被 go 覆写；go 必须有可行主路；出发窗口起止必须有效。
C 仍需负责：预测窗口内未来可行性、备选共享故障点、解释真实性、正式模型校准。A 不会把 C 的规则分数当准时概率。
不提供 decide 时，decision 为 null，A 核心依然可独立运行。

## A → D：地图、展示与 HTTP

正式组合结果类型：`TeamJourneyResult`。D 读取：

| 字段 | 用法 |
|---|---|
| `routes[].candidate.journey.segments` | 逐段地图／交通说明／跨境段 |
| `segment.geometry` | `[lon, lat]` 折线；Leaflet 需转成 `[lat, lon]` |
| `segment.kind / border` | 通关段、口岸、排队区间 |
| `routes[].assessment.risk` | 五因子、风险等级及证据 |
| `routes[].assessment.reliability` | ETA 区间、定性信心及声明 |
| `eligible / exclusions / meetsDeadline` | 禁用、不可行原因、到达超时 |
| `recommendedRouteId` | A 基础推荐 |
| `decision` | C 正式决策（未接入时 null） |
| `data / notices` | 品质、来源、更新时间与降级提示 |

辅助函数：`journeyGeometry(journey)`、`borderSegments(journey)` 从 `@/lib/integration` 导入。
UI 必须展示 reliability.confidenceNote，不能将 ruleScore/rankScore 显示成百分比。

现有演示 HTTP：`POST /api/journey`，请求／回应用 `types/journey-analysis.ts`。
它与正式组合 `TeamJourneyResult` 是**两份明确命名的契约**，不能直接强制类型转换。
若 D 要保留现有演示 UI，由 A 在服务端写显式字段映射；或 D 直接消费 TeamJourneyResult 开发正式界面。
当前默认 HTTP 仍运行演示；接正式 B/C 时在服务端 API 内调用示例的 evaluateTeamJourney，并返回该结果。API 应验证请求、处理异常、使用 no-store；不得把供应商凭证发送给浏览器。

## E → D：视觉规格

类型与参考值：`app/src/lib/integration/ui-contract.ts`。

```ts
import type { JourneyVisualSpec } from '@/lib/integration';
import { REFERENCE_JOURNEY_VISUALS } from '@/lib/integration';
```

E 可按该形状提供 low / medium / high / critical 标签、颜色、非颜色符号、跨境虚线和 unavailable 规范。
这些是可替换参考 token，现有演示地图尚未自动读取该规格；D 集成时替换演示里的颜色常量/CSS。
风险算法保持 low / medium / high 三档；critical 可用于 C 的人流信号与对应视觉，不能凭视觉新增算法等级。

## 合并和验收

B/C/D/E 交付各自目录及测试；A 在组合层接入。共享类型变更先提变更说明。

```sh
npm run typecheck
npm test -- src/test/team-integration.test.ts
npm run verify
```

必须验证：正常／资料缺失／过期／超时回退／不同口岸／深夜关闭／服务中断／严重天气／相同输入确定性。
