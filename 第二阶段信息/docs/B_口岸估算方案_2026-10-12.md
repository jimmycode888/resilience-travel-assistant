# 口岸数据能不能估？—— 可行方案与真实跑通的原型（2026-10-12）

**结论先行：能估，但只能估「区间 + 置信度」，永远不能估出精确分钟数。**
而且更值钱的一件事是：**口岸的「开放时间 / 可通行方式」根本不用估，它是可以核实的「事实」**——
现在之所以标着未核实，是没人去查，不是查不到。

下面所有信号都在今天（2026-10-12 22:35 HK）**真实跑通过**，原型脚本可复现：
`node scripts/port-queue-estimate-probe.mjs`

---

## 一、先说清楚「能估什么 / 不能估什么」

| | 内容 | 性质 |
|---|---|---|
| ✅ **能做成事实** | 口岸清单、开放时间、可通行方式、末班车时间 | **核实**，不是估算 |
| ✅ **能估成区间** | 排队时间（当前时段） | 区间 + confidence，必须带依据 |
| ✅ **能直接判定** | 口岸此刻开没开、会不会在到达前关闭 | 硬判定，比排队更重要 |
| ❌ **永远估不出** | 精确到分钟的排队、真实等候人数 | 没有任何公开来源观测它 |

> 硬约束不变：**严禁编造**精确排队时间。区间之外的一切都如实标注为估算。

## 三、估算模型（可解释、可复现、可回退）

```
排队区间 = 基础区间(口岸类型 × 时段 × 方向)
         + 周末/假日加成
         + 恶劣天气加成        ← 来自信号 3
         + 深夜修正            ← 来自时刻
         + 运力变薄加成        ← 来自信号 1、2（实测班距显著大于常态）
         + 口岸事件加成        ← 来自信号 4
         + 铁路中断加成        ← 来自信号 5（仅落马洲/罗湖）
```

**基础区间（先验，未经历史数据校准）**

| 口岸类型 | 高峰 | 平峰 | 深夜 |
|---|---|---|---|
| `rail`（落马洲、罗湖） | 15–35 | 5–15 | 3–10 |
| `coach`（深圳湾、香园围、皇岗） | 20–45 | 10–25 | 5–15 |
| `small`（文锦渡） | 25–55 | 15–35 | 8–20 |

**时段**：北向高峰 07:00–10:00、南向高峰 17:00–20:00；深夜 22:30 后。
**加成**：周末 +10~20、恶劣天气 +10~25、运力变薄 +5~15、口岸事件 +10~30、铁路中断 +15~35、深夜 −3~0。

**置信度规则**：有 ≥3 个 live 信号 → `medium`（**上限就是 medium**）；否则 `low`；口岸关闭 → 不产出区间（直接不可行）。

## 五、诚实边界（这套方案的天花板在哪）

1. **没有源观测排队本身**。所有信号都是**间接代理**，所以置信度上限只能是 `medium`，`high` 是不诚实的。
2. **班距是时刻表驱动的，不是需求驱动的**。港铁/巴士按计划发车，班距变长不等价于人少。
   因此信号 1、2 只能当「运力佐证」，**不能反推客流**。想真正反映需求，需要运力侧数据（现无公开源）。
3. **基础区间是假设**，不是标定值。要让区间站得住，需要：官方公开的排队统计、历史问卷/观测采样，或与运营方口径对齐——**目前都没有**。
4. **2 个口岸没有任何信号**（皇岗、文锦渡），只能低置信度。
5. **开放时间不核实，一切都白搭**：判定开关用的是未核实值，估得再细也是错的。

## 六、建议的落地顺序

| 优先级 | 做什么 | 产出 |
|---|---|---|
| **P0** | **核实 6 个口岸的开放时间 / 可通行方式 / 坐标**（入境处 + 海关 + 港铁首末班 + 运营方页面），把 `coordinatesVerified` 改成 `true` | 事实层，`DATA_SOURCES.md` 跨境一节 |
| **P0** | 把**排队模型独立成 B 的一份数据 + 纯函数**，让 C 的 `border/thresholds.ts` 改为消费它（现在 B/C 两套区间不一致） | 单一权威来源 |
| **P1** | 接**东铁过境段**（LMC/LOW/SHS）+ **九巴 ETA**，补上运力信号 | 4→6 个口岸有信号 |
| **P1** | 模型里加**时区/节假日**表（香港公众假期），替代「周末」粗判 | 假日峰值不再漏 |
| **P2** | 若要与官方对表，联系运营方/查阅公开统计做**一次标定**，把基础区间从假设升级为有依据 | confidence 才有机会到 medium-high |

## 七、需要 A / C 配合

- **A**：排队模型要作为 `RouteSegment.border.queueMinutesRange` 的**唯一来源**；`border` 契约需容纳「依据列表 + confidence」。
- **C**：`src/lib/border/thresholds.ts` 的 `BORDER_QUEUE_BASE` 应与 B 的模型合并，避免两套区间。
- **D**：UI 必须区分「**核实的事实**」（开放时间/末班车）与「**估算**」（排队区间），不能都打同一个「实时」徽章。
