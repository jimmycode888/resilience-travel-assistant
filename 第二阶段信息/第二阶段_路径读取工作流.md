# 第二阶段工作流 · 出行／导航路径读取

适用范围：把「起点 + 终点 + 时间」变成可交给风险引擎的候选路线。
工作目录：`~/Desktop/八校黑客松`（第二阶段代码直接在根目录，不另建目录）
跨境优先级：**最高**（W2、W4、W7 都以跨境为第一验收对象）

**独立可用判据（Definition of Independently Usable）**
本工作流完成时，下面每条都必须能独立成立，不依赖任何未完成的模块：

- [ ] 无网络、无任何环境变量、无密钥时，仍能给出 ≥2 条候选路线（fixture）
- [ ] 每条候选都带：分段、时间推进、几何折线、跨境归属、口岸绑定
- [ ] 跨境行程一定有 `border_crossing` 段与口岸 ID，且排队是**区间 + 置信度**
- [ ] 换口岸（跨境 Plan B）可按口岸筛选
- [ ] 口岸关闭时段不会被当作可行方案
- [ ] live / cached / fixture 三退路各自可命中且如目标示
- [ ] 同一输入永远得到同一输出（决定性）
- [ ] `npm run verify` 全绿

## W3 解析器（路径读取的心臟）

| 项 | 内容 |
|---|---|
| 负责人 | A |
| 输入 | `RawJourney` |
| 具体操作 | `src/lib/route/parse.ts` |
| 产出 | `parseRawJourney()` → `{ journey, notices }` |
| 验收 | `npx vitest run src/test/route-parse.test.ts`（15 测试） |

**解析器负责四件事**（顺序固定）：

```text
1 交通方式對照   供應商字串 → 內部 JourneyMode（未識別者按巴士處理並回報）
2 跨境判定       比較兩端 side → in_hk / border_crossing / in_sz，並用 portBetween 綁定口岸
3 時間推進       由 departAt 起算，逐段加總（後段出發 = 前段抵達）
4 幾何補齊       供應商沒給座標時用起終點連線，並**明確提示**（不得假裝有路網資料）
```

**設計約束**：解析器只認識中立格式 `RawJourney`，所以新增供應商不需要改解析邏輯與測試。

**狀態：✅ 已完成**

## W5 編排與三退路

| 項 | 內容 |
|---|---|
| 負責人 | A |
| 具體操作 | `src/lib/route/adapter.ts` |
| 產出 | `resolveRoutes()` → `{ resolution, tier }` |
| 驗收 | `npx vitest run src/test/route-crossborder.test.ts`（18 測試） |

**三退路規則**

```text
① 快取（標示 cached，並說明可能不是最新路況）
② 實時供應商（依序嘗試；逾時或失敗 → 記錄 notice 後往下）
③ fixture（永遠的最後保險，保證斷網也能演示）
```

**刻意設計的兩條規則**

1. **fixture 結果不進快取** —— 否則真實來源恢復後會被舊的 fixture 蓋住。
2. **篩選條件不可以把候選變空** —— 指定口岸／交通方式若篩掉全部候選，
   就保留原候選並回報。因為「一個建議都沒有」對使用者的傷害大於「給出不完全符合條件的建議」。

**狀態：✅ 已完成**

## 異常路徑處理（每一條都已被測試覆蓋）

| 情況 | 系統行為 |
|---|---|
| OSRM 逾時 / 失敗 | 記錄 notice → 回退 cached → 回退 fixture |
| 供應商回傳空結果 | 同上 |
| 出發時間無法解析 | 拋 `INVALID_DEPART_AT`，API 層轉明確錯誤 |
| 找不到對應走廊 | 拋 `NO_ROUTES`（不回傳空陣列，避免前端白屏） |
| 某條候選格式異常 | 只略過該條並回報，其餘候選照常回傳 |
| 通關段缺排隊資料 | 不編造數值，`border` 留空並明確提示 |
| 未知地點 | 用最近口岸推斷側別，並標示 `sideSource: "heuristic"` |
| 指定口岸無候選 | 保留全部候選並回報，不讓結果變空 |
