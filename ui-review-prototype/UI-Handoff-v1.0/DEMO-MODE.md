# Demo Mode — `?demo=1`

## 1. 唯一的 Demo 機制

| 項目 | 值 |
|---|---|
| 開關 | URL query `?demo=1` |
| 例 | `http://localhost:8443/?demo=1` |
| 預設（無參數） | **完全不渲染** demo 面板（DOM 中不存在） |

## 2. 預設使用者看到什麼

- **沒有**情景切換按鈕（正常通勤／暴雨影響／交通中斷一律不出現）。
- 情境由系統判定，UI 只**顯示結果**：
  - 頂欄狀態徽章：`當前狀態：正常` / `當前狀態：暴雨影響` / `當前狀態：交通中斷`
  - 結果頁服務標籤：`推薦路線：服務正常` 等（由 `primaryPlan.status` 驅動）
- 預設載入 `normal` 情景。

## 3. Demo 模式額外顯示什麼

一個可折疊面板，執行下列兩組控制：

| 控制 | 選項 | 說明 |
|---|---|---|
| 系統判斷的情景 | 正常通勤 / 暴雨影響 / 交通中斷 | 模擬「系統判定為哪個情景」 |
| 界面狀態 | 依資料 / 加載中 / 不可用 / 錯誤 | 模擬各狀態畫面 |

面板文字明示：

> 演示控制（僅用於演示，不屬於使用者介面）
> 真實產品中情景由數據與系統判定，用戶不選擇情景。此面板僅用於比賽演示。

## 4. D 的實作要求

- **不要把 scenario selector 做進正常使用者流程。**
- 正式產品中情景必須由資料與系統判定（天氣警告、交通公告、服務狀態）。
- 若 D 也需要一個 demo 入口，請沿用相同精神：**預設隱藏、明確標示僅供演示、不影響使用者流程**。
- `?demo=1` 為本 Baseline 認可的演示開關（團隊決定 ①，2026-10-08）。
