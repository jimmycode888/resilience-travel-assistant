# UI-States — 五種狀態（UI Baseline v1.0）

> 狀態由 `DecisionResponse.status` 與資料載入階段決定。**五種狀態都不得出現白屏。**

| 狀態 | 觸發條件 | 是否保留完整建議 |
|---|---|---|
| `loading` | 使用者提交後、請求尚未完成 | — |
| `ready` | `status === "ready"` | ✓ |
| `uncertain` | `status === "uncertain"`（信心 low 或缺 Plan B） | **✓ 必須保留** |
| `unavailable` | `status === "unavailable"`（無任何路線滿足限制） | ✗（本來就沒有可行路線） |
| `error` | 請求失敗（網路／HTTP 錯誤） | ✗ |

---

## loading

**使用者提交後：**

- 顯示 loading 狀態卡片，**不顯示錯誤**、**不顯示空白頁**。
- 內容（逐字）：

  > 正在分析
  > **正在讀取路線狀態與天氣資料**
  > 我們正在整合最新天氣與交通資料，通常只需幾秒。

- 視覺：置中卡片 + 旋轉指示器 + 骨架屏（三條灰條，寬度 82% / 58% / 70%）+ 小字 `正在讀取路線狀態與天氣資料…`
- 這是**即時請求**的自然過渡，非 Demo 專用。
- 行動版最小高度 340px、桌面 420px。

## ready

- 顯示完整正常結果（決策摘要 + 路線概覽 + Plan B + 切換條件 + 風險 + 推薦理由 + 資料來源 + 免責聲明）。
- 頂欄狀態徽章顯示系統判定情景（如 `當前狀態：正常`）。
- 結果頁右上顯示 `推薦路線：服務正常`（由 `primaryPlan.status` 驅動）。

## uncertain ← 最容易被誤解的狀態

**必須說清楚的三件事：**

1. **`uncertain` 不是 `error`。** 它是一次**成功**的決策結果，HTTP 200。
2. **`uncertain` 不是 `unavailable`。** 它**有**可執行路線，只是信心較低或沒有 Plan B。
3. **必須保留完整建議**，不可把結果清空成一張狀態卡。

**畫面要求：**

| 要求 | 實作 |
|---|---|
| 保留完整建議 | ✓ 決策摘要、路線概覽、Plan B、切換條件、風險、理由全部照常顯示 |
| low confidence 要明顯 | ✓ 決策摘要內 `到達信心：低` + 只有 1 格亮起；另在頂部加琥珀色橫幅 |
| 顯示主路線 | ✓ 由 `primaryPlan`（disruption 時為 R2 過海巴士） |
| 顯示 Plan B（若真實資料提供） | ✓ 由 `planBPlan`（disruption 時為 R3 港鐵經鰂魚涌） |
| 顯示 `uncertainty` | ✓ 獨立「我們不知道什麼」卡片（全部條目） |
| 顯示 `excludedRoutes`（若真實資料提供） | ✓ 「其他候選路線」卡片內的「已排除路線」區塊（預設可見） |

**琥珀色橫幅文字（逐字）：**

> ⚠ **建議可用但不確定**
> 出發前請再確認港鐵、運輸署與香港天文台的官方公告。
> （另列出 `uncertainty` 的前 3 條）

> **實例**：`disruption`（交通中斷）情景本身就是 `uncertain` + `confidence: low`。

## unavailable

**原則：不應該假裝有可執行路線。**

- 顯示狀態卡（逐字）：

  > 資料狀態
  > **實時建議暫時不可用**
  > 未能取得足夠的交通資料。你仍可查看固定時刻表。

- **`action` 語意**：真實 API 此時回 `action: "hold"`（`留在安全處持續觀察`）。UI 以文字呈現，不假裝有出發時間。
- **必須給出下一步操作**（三個出口）：

  | 按鈕 | 行為 |
  |---|---|
  | `調整行程條件`（主按鈕） | 返回輸入頁重新設定 |
  | `查看原因`（次按鈕） | 捲動至「為什麼沒有可行的建議」卡片 |
  | `或留在安全處持續觀察`（文字提示） | 對應 `action: hold` 的語意 |

- 狀態卡下方另顯示真實內容：
  - **為什麼沒有可行的建議**：逐條列出 `reasons`（會說明哪條路線因什麼限制被排除）
  - **其他候選路線**：`excludedRoutes` + `candidates`
- **不顯示**出發時間、到達區間（契約此時為空字串）。

## error

- 顯示狀態卡（逐字）：

  > 資料狀態
  > **建議未能載入**
  > 連接出現問題，請稍後重試。你的行程資料已保留。

- **操作**：
  - `重試`（主按鈕）→ 重新發出請求
  - `返回輸入頁`（次按鈕）→ 回到輸入頁，已填資料保留
- **不偽造 error code**：真實 HTTP 400/500 會帶 `error.code`（如 `INVALID_INPUT`、`INTERNAL_ERROR`）；本 Prototype 的 error 為 Demo 模擬、非真實請求失敗，因此**不顯示任何錯誤代碼**。
  - D 若接上真實 API：**可以**顯示真實回應中的 `error.code`；若沒有，就不要顯示。
- 狀態卡期間**不顯示**服務標籤（避免與錯誤語意衝突）。

## 狀態矛盾檢查（Baseline 已驗證）

| 禁止的組合 | Baseline 狀態 |
|---|---|
| 「交通中斷 + 服務正常」寫死字樣 | ✅ 不存在（頂欄改為隨情景變化的系統狀態；服務標籤由 `primaryPlan.status` 驅動） |
| 「unavailable + 服務正常」 | ✅ 不存在（unavailable 時不顯示服務標籤） |
| 「uncertain 卻顯示高信心」 | ✅ 不存在（disruption 為 `low`，量表只亮 1 格） |
| `loading` 期間顯示錯誤 | ✅ 不存在 |
