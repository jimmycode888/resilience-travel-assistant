# UI-Screens — 頁面結構說明（UI Baseline v1.0）

> 全部字串為 **UI 實際顯示的繁體文案**（逐字引用）。D 實作時文案以本 Baseline 為參考。

Prototype 是單頁應用（SPA），**沒有路由**：`page` 狀態在「輸入頁」與「結果頁」兩個視圖間切換。

---

# Page 1 — 輸入頁

## 1.1 版面

- 桌面（>900px）：兩欄 grid，左＝介紹區（`0.85fr`），右＝表單卡（`1.15fr`），間距 72px，最大寬 1200px。
- 行動（≤900px）：單欄堆疊；介紹區在表單之上。

## 1.2 欄位（共 5 項，**不得新增**）

| # | UI 標籤（逐字） | 控制項 | 必填 | 允許值 | 預設 |
|---|---|---|---|---|---|
| 1 | `起點` | `select` | ✓ | 契約走廊起點：`坑口（富寧花園）`、`坑口站 A 出口` | 坑口（富寧花園） |
| 2 | `終點` | `select` | ✓ | 契約走廊終點：`中環（交易廣場）`、`中環（國際金融中心二期）` | 中環（交易廣場） |
| 3 | `最遲到達時間（香港時間）` | `datetime-local` | ✓ | 含日期與時間 | `2026-10-13T09:00` |
| 4 | `可接受的額外車費（HK$）` | `number` | ✓ | 整數 `0–500`，**`0` 是有效值**（表示只接受不額外付費的方案） | `10` |
| 5 | `可接受的轉乘次數` | `number` | ✓ | 整數 `0–5`，**`0` 是有效值** | `2` |

- 起點／終點**只能是契約列舉值**（`API_CONTRACT.md §2.1`），不是自由輸入。
- 額外車費與轉乘次數在契約中為**必填 hard constraints**（前端以預設值呈現）。
- 輸入頁**不得**加入 weather、scenario、路線偏好等契約外欄位。

## 1.3 驗證方式

與 `resilience-travel-assistant/src/lib/validation.ts` 規則一致：

| 條件 | 訊息（逐字） |
|---|---|
| 車費非整數／超出 0–500／空 | `可接受的額外車費必須是 0–500 的整數（0 表示只接受不額外付費的方案）。` |
| 轉乘非整數／超出 0–5／空 | `可接受的轉乘次數必須是 0–5 的整數。` |
| 未選到達時間 | `請選擇最遲到達日期與時間。` |

- 全部為**提交時**驗證（`noValidate`），不即時驗證。
- **允許 0**：車費 0 與轉乘 0 皆通過前端驗證（`0` 不是空值、不觸發任何錯誤）。

## 1.4 錯誤提示位置

- 錯誤清單渲染於**表單欄位下方、CTA 上方**（`ul.field-errors`，`role="alert"`）。
- 樣式：淺紅底、紅色細框、紅字；多筆以清單逐條列出。
- 驗證失敗時**不送出、不跳頁**，使用者留在輸入頁。

## 1.5 CTA 行為

| 項目 | 值 |
|---|---|
| 文字 | `獲取出行建議`（含右箭頭圖示） |
| 位置 | 表單最下方，滿寬 |
| 行為 | 驗證通過 → 以表單值組出請求並切換到結果頁；不通過 → 只顯示錯誤 |
| 行動版 | **取消 sticky**（曾經 sticky 會遮擋欄位）；實測捲動時遮擋欄位數 = 0 |
| 輔助文字 | `建議會優先確保你在 HH:mm 前到達`（HH:mm 取自使用者輸入的到達時間） |

## 1.6 Mobile 佈局（390×844）

- 單欄；`起點` / `終點` / `最遲到達時間` / `額外車費` / `轉乘次數` 依序縱向排列。
- CTA 滿寬、位於表單底部（隨頁面捲動，不固定）。
- 無橫向溢出。

# Page 2 — 結果頁

## 2.1 資訊層級（UI Reference 順序）

D 應**盡可能還原**下列順序；若真實 API 回傳欄位不同，**以 API Contract 為準**，並**不得**為了對齊本順序而創造 API 欄位。

### 第一屏（決策摘要 `DecisionSummary`）

| 順序 | 元素 | 對應欄位 |
|---|---|---|
| 1 | **行動建議**（徽章，如 `按建議時間出發`） | `action` |
| 2 | **建議出發時間**（最大字級）`建議 08:09 出發` | `departAt` |
| 3 | **最遲出發時間** `最遲出發 08:15` | `latestDepartAt` |
| 4 | **到達區間** `08:54 – 09:04` | `etaRange` |
| 5 | **到達信心** `到達信心：高` + 三格量表 | `confidence` |
| 6 | **推薦路線**（摘要帶）label + 全程／轉乘／額外車費 | `primaryPlan` |

> 依 `§6` 要求，第 1–5 項必須在結果頁第一屏清楚可見（實測桌面 y≤360、行動 y≤470）。

### 之後（內容區）

| 順序 | 區塊 | 對應欄位 | 備註 |
|---|---|---|---|
| 7 | **路線概覽**（路線帶 + 統計 + 可折疊時間軸） | `primaryRoute`、`primaryPlan` | |
| 8 | **Plan B** | `planB`、`planBPlan` | 無 Plan B 時顯示「本次沒有可用的備用路線…」 |
| 9 | **切換條件**（深色高亮區塊） | `switchCondition`、`switchDeadline` | 必須獨立成塊 |
| 10 | **風險** | `primaryPlan.status`、`riskNotes` | 文字 + 圖示，不只靠顏色 |
| 11 | **推薦理由** | `reasons`、`basis` | `basis` 收在可展開區 |
| 12 | **我們不知道什麼** | `uncertainty` | |
| 13 | **其他候選路線 / 已排除路線** | `candidates`、`excludedRoutes` | 預設折疊 |
| 14 | **資料來源** | `dataSources`、`dataUpdatedAt`、`dataQuality` | |
| 15 | **免責聲明** | `disclaimer` | |

補充區塊（依狀態出現）：

- **提醒**（`notices`）：琥珀色提示條，位於決策摘要之後。
- **不確定提示**（`status === "uncertain"` 時）：琥珀色橫幅，位於決策摘要之後、提醒之前。

## 2.2 Desktop 版面（1440 × 900）

- 頁面最大寬 **1260px**，左右內距 28px。
- 決策摘要卡片滿寬；下方 `result-grid` 為 **1.5fr : 0.8fr 雙欄**：
  - **左欄**：路線概覽 → Plan B
  - **右欄**：切換條件 → 風險 → 推薦理由 → 我們不知道什麼
- 底部滿寬：其他候選路線 → 資料來源 → 免責聲明。
- 切換條件位於 **y=512**（首屏內）。

## 2.3 Mobile 版面（390×844）

- 單欄，順序與 §2.1 一致（路線概覽 → Plan B → 切換條件 → 風險 → 推薦理由 → 我們不知道什麼 → …）。
- 路線時間軸與 Plan B 步驟**預設折疊**（桌面預設展開），以縮短頁面。
- **切換條件位於 y=1199**，**不要求**塞進 844px 首屏（團隊決定）。
  - 向下捲動一定有內容（頁面總高約 3,139px），不會讓人誤以為到底。
  - 切換條件**不被隱藏、不被折疊**。
  - `switchDeadline` 已在「切換條件」區塊內以大字顯示（`最遲切換決定：07:49`）。
  - 是否要在決策摘要提前提示 `switchDeadline`，屬**待 E 決策事項**（見 `BASELINE-MANIFEST.md §6`）。
- 統計列 4 欄、卡片內距縮至 12px、決策摘要內距縮至 18/14px。

## 2.4 響應式斷點

| 斷點 | 行為 |
|---|---|
| `> 900px` | 桌面雙欄（輸入頁 2 欄、結果頁 2 欄、時間軸預設展開） |
| `601–900px` | 輸入頁轉單欄；結果頁以 `display:contents` + `order` 拍平為單欄（順序同 Mobile） |
| `≤ 600px` | 行動優化：單欄表單、字級／內距壓縮、時間軸預設折疊、部分 metadata 隱藏 |

- 全尺寸**無橫向溢出**（實測 1440×900、390×844）。
